## Ce que cela change pour qrg-meter et les traces OTel

**qrg-meter.** Aucun des deux compteurs n'est réutilisable : dsh-balance-meter mesure le solde d'un compte DeepSeek et chiffre en CNY d'après une page de prix chinoise, dsh-live-stats estime des tokens DeepSeek pendant le flux. La pastille se construit sur trois points d'extension DSH vérifiés.

- Tokens natifs : la projection durable `tokenUsage` de `dsh-token-meter` additionne l'usage rapporté par le fournisseur dans `assistant/message` et `assistant/attempt` (`packages/llm/token-meter/src/usage-projection.ts:1-2, 80-85, 113-118`). Les projections sont des plis purs rejoués depuis le journal, leur cache n'étant qu'un raccourci (`packages/session/session-projection/src/index.ts:1-17, 119-126`) : C-05 est acquis sans stockage propre.
- qrg-meter enregistre sa propre projection par `ctx.sessionProjections.register`, motif suivi par `packages/llm/token-meter/src/index.ts:114` et par dsh-live-stats (`src/index.ts:17-19`), agrège les enfants par `header.parentSession` (C-04) et retranche le surcoût d'orchestration (C-02).
- Claude Code : le fournisseur officiel `subagent-claude-code` laisse l'usage hors de la session parente (`packages/subagent/subagent-claude-code/README.md:12`). qrg-claude-code doit écrire l'usage du message de résultat de l'Agent SDK comme événement du journal pour que la projection le replie et le restaure.

Affichage : slot `conversation.composer.dock`, où DSH place déjà ses pastilles `activity` et `usage`, remplaçables par identifiant (`packages/client/ui-chat/src/client/apply.ts:321-330`) ; dsh-balance-meter y pose sa puce (`src/client/index.ts:47-54`), mais une vue client de projection évite son interrogation HTTP toutes les 30 s. Prix (C-06) : la grille par token configurable de dsh-observe (`src/config.ts:554-572`) est un bon modèle, le moissonnage de page de dsh-balance-meter ne l'est pas.

**Traces OTel.** Base : fork de loongsuite/dsh-plugin gelé sur `f44ccfc` (Apache-2.0, SDK OpenTelemetry officiel, conventions GenAI récentes, attributs de délégation déjà posés). Modifications à prévoir :

- `captureContent` forcé à faux, sans repli sur l'environnement ; retrait de `dsh.session.cwd`, `host.name` et de l'attribut ARMS ;
- en-têtes d'export et clés résolus par `ctx.credentials`, donc par le courtier de secrets (S-02), au lieu de chaînes en clair dans la config ;
- `engines.dsh` sur 0.2.x et tests sur 0.2.1 ;
- masquage porté depuis `src/sanitize.ts` de dsh-observe (Apache-2.0), motifs élargis à `sk-ant-`, `sk-proj-` et aux JWT ;
- spans décision, délégation et `ask_user` dans le même fournisseur de traces, contenu de question masqué par défaut (S-03) ; trace enfant reliée au parent par un lien de span ;
- total de trace corrigé pour Langfuse (issue #3), et tampon durable si la perte de spans pendant une panne du collecteur est inacceptable.

Aucun des deux plugins OTel ne voit une délégation Claude Code ni n'offre d'API à un autre plugin pour ajouter des spans dans sa trace : le span de délégation viendra de QRG, donc du fork.

## Points transverses DSH

Contrôle de version : DSH 0.2.1 ne lit que `engines.dsh`, sinon les peers `@deepseek-ai/dsh*` ; sans l'un ni l'autre, il admet le plugin sans contrôle (`packages/boot/app-boot/src/plugin-compatibility.ts:55-74`), et un bundle hors plage est écarté sauf dérogation exacte `nom@version` (`packages/boot/app-boot/src/profile.ts:760-766`, `packages/boot/app-boot/src/compatibility-preflight.ts:105-106`). Le fork qrg-otel doit donc déclarer `engines.dsh`.

Scripts d'installation : DSH installe par pnpm 11, qui bloque les scripts des dépendances ; l'approbation peut venir de la page Plugins ou de l'outil `install_bundle` (`approvedBuilds`) après accord de l'utilisateur dans la conversation, accord que le service ne vérifie pas (`packages/boot/plugin-manager/README.md:64`). Un agent manipulé pourrait donc approuver un script : à couvrir par S-01 et S-05.

Gel sur SHA : DSH accepte des spécifications git avec référence, du type `github:<owner>/<repo>#<sha>` (`packages/boot/plugin-manager/src/install-spec.ts:22-24`). La détection au démarrage d'un commit changé (S-04) reste à construire dans QRG (hypothèse non vérifiée : DSH ne la fait pas).
